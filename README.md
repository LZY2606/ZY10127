# Battery Lab 本地电池协议演练台

这是一个不控制真实电源的 Spring Boot 本地应用。它用可确定推进的虚拟时钟执行电池测试协议，接收设备测点，模拟掉线、重启、设备故障和人工复核，并把原始测点与派生分析结果分离保存。

## 技术栈与启动

- Spring Boot 3.5，Java 21 字节码，可在当前 JDK 上运行。
- SQLite 文件数据库，默认 `battery-lab.db`，可用 `BATTERY_LAB_DB=/path/to/file.db` 覆盖。
- 浏览器端为无构建步骤的静态 HTML/JavaScript。
- 设备模拟器只根据协议、步骤已用时间和周期序号计算测点；没有随机数，也不读取墙钟推进协议。

安装：

```bash
mvn -q -DskipTests package
```

测试并演示：

```bash
mvn -q test && mvn -q spring-boot:run -Dspring-boot.run.arguments=--server.port=5327
```

浏览器打开：

```text
http://127.0.0.1:5327
```

## 内置版本和协议

协议、积分规则和设备能力分别独立版本化：

- `protocol/v1`：2 个周期，采样间隔 1000 ms，步骤为恒流充电、恒压截止、充电后静置、恒流放电、放电后静置、循环跳转。
- `rules/v1`：左矩形积分，端点归出向步骤；用于“按原规则重算”的对照规则。
- `rules/v2`：默认规则，按周期边界和步骤端点切分后做梯形积分；边界两侧的入向电流按 0 A 处理。
- `capability/v1`：设备 `cell-001`，电压 0–6 V，电流 -5–5 A，温度 -10–80 °C，采样间隔 1000 ms。

每次运行都会复制当时的协议、规则和能力 JSON 快照。后续修改版本定义不会改变历史运行。

## 单位与方向约定

- 虚拟时间：毫秒（ms），从每个运行的 `0` 开始。
- 电压：伏特（V）。
- 电流：安培（A），正数表示充电，负数表示放电。
- 温度：摄氏度（°C）。
- 积分中间量：安培秒（A·s），结果容量换算为安培小时（Ah），`1 Ah = 3600 A·s`。
- 库仑效率：`放电容量 Ah / 充电容量 Ah`，无量纲；充电容量为 0 时结果为 `null`，不强行生成比率。
- 传感器排除段：半开区间 `[startAtMs, endAtMs)`，被完全覆盖的积分段从派生结果中剔除，原始测点不删除、不覆盖。

## 积分口径

测点时间戳允许不等间隔。积分器先按以下切点切分时间轴：

1. 周期开始和结束边界；
2. 协议步骤转移事件的时间点；
3. 每个已确认或迟到确认测点的时间戳。

`rules/v1` 使用左矩形积分：

- 积分段 `[t_i, t_{i+1})` 的电流取左测点电流；
- 恰好落在步骤端点的测点归出向步骤；
- 跨周期共享端点不会被下一周期重复消费。

`rules/v2` 使用切分后的梯形积分：

- 积分段电流面积为 `(I_left + I_right) / 2 × Δt`；
- 在步骤或周期边界的入向侧按 0 A 处理，防止静置、充电、放电之间串电流；
- 出向侧仍保留端点原始电流，以保留出向步骤最后一个积分半步；
- 周期边界也作为切点，边界测点不会在相邻周期重复累计。

没有测点覆盖的时间不做外推。被排除的故障段不会插值补足容量，而是计入该周期的 `excludedMs` 并提示研究员复核。

## 两阶段测点确认

模拟器的“推进并上报”和研究员/设备的“确认写入”是两个独立 HTTP 操作：

1. `POST /api/runs/{id}/simulator/advance` 生成下一个测点，状态为 `PENDING`。
2. 设备在上报成功后、确认前掉线时，测点仍保留在 SQLite 中。
3. 重连后调用 `POST /api/runs/{id}/samples/{sequenceNumber}/confirm`，同一个 `PENDING` 测点变为 `CONFIRMED`。
4. 重复确认同一个序号是幂等的；已有 `CONFIRMED` 或 `LATE` 测点会返回原记录。
5. `(run_id, device_sn, sequence_number)` 有唯一约束。同一序号再次上报但载荷哈希不同：
   - 原测点状态变为 `CONFLICT`；
   - 冲突载荷写入 `conflict_attempts`；
   - 运行进入终态 `CONFLICT`；
   - 旧载荷绝不覆盖。

载荷哈希覆盖设备序号、测点序号、采样时间、电压、电流和温度。

## 阈值、迟到样本和周期边界

- 电压或电流阈值只有在“新样本确认后”发现越过阈值时才会转移步骤。
- 尚未确认的 `PENDING` 样本不会改变当前步骤。
- 已经发布的步骤不允许倒退。确认时间早于或等于最后确认时间的样本被标为 `LATE`，状态机仍停在已发布位置。
- 迟到样本仍作为原始测点保存，并重算一个新的、不可变的派生版本，该版本 `needsReview=true`。
- 恰好落在端点的测点参与积分；协议在该测点确认后原子写入步骤事件和运行头。
- 循环跳转是零时长协议节点。放电后静置的最后一个测点确认时，系统原子写入跳转事件并把下一点放到新周期第 0 步；图上仍保留跳转节点用于表达协议结构。

## 运行状态转移

| 状态 | 含义 | 可进入方式 | 后续动作 |
| --- | --- | --- | --- |
| `RUNNING` | 可接收测点并推进 | 新建、暂停后继续、新周期开始 | 推进、确认、暂停、掉线、取消、故障、冲突 |
| `PAUSED` | 可恢复的暂停态 | 研究员暂停 | 可继续；可取消或注入设备故障 |
| `COMPLETED` | 正常完成终态 | 完成最后周期 | 只读，不可复活 |
| `CANCELLED` | 研究员取消终态 | 取消运行 | 只读，不可复活 |
| `DEVICE_FAULT` | 设备故障终态 | 注入设备故障 | 只读，不可重启恢复 |
| `CONFLICT` | 重复序号异载荷冲突终态 | 第二载荷哈希不同 | 只读，保留冲突证据，不可复活 |

掉线只改变设备连接标记并记录 `DEVICE_OFFLINE`，不等于暂停或故障。重连记录 `DEVICE_ONLINE`。设备重启只允许在 `RUNNING` 或 `PAUSED` 这类可恢复状态下执行；任何终态调用重启都会得到冲突响应。

中断原因独立保存为 `NONE`、`PAUSED`、`CANCELLED`、`DEVICE_FAULT`、`CONFLICT`、`COMPLETED` 或 `LATE_SAMPLE`。终态运行有 `endedAtMs`，不能被后续操作复活。

## 派生结果与研究员修正

派生结果保存在 `derivations` 和 `cycle_results`：

- 周期边界确认后生成 `CYCLE_BOUNDARY` 版本；
- 运行正常完成后生成 `COMPLETED` 版本；
- 迟到样本生成 `LATE_SAMPLE` 版本并标记复核；
- 人工修正周期边界生成 `BOUNDARY_CORRECTION` 版本；
- 排除传感器故障段生成 `EXCLUSION` 版本；
- 选择规则版本重算生成 `RECOMPUTE` 版本。

旧版本永不就地更新。每个版本记录父版本、规则版本、边界列表、排除段、复核原因和每个周期的充电容量、放电容量、库仑效率。

## REST 摘要

- `GET /api/versions`：查看协议、规则和能力版本。
- `POST /api/runs`：创建运行，可指定规则版本。
- `GET /api/runs/{id}`：聚合查看协议快照、当前步骤、设备连接、原始测点、事件、边界、排除段和所有派生版本。
- `POST /api/runs/{id}/simulator/advance`：虚拟时钟推进一个采样间隔并上报。
- `POST /api/runs/{id}/samples/{seq}/confirm`：确认测点写入。
- `POST /api/runs/{id}/samples`：手工上报测点，便于迟到样本测试。
- `POST /api/runs/{id}/pause|resume|cancel`：暂停、继续、取消。
- `POST /api/runs/{id}/device/offline|online|restart|fault`：设备连接与故障注入。
- `POST /api/runs/{id}/boundaries/{cycle}`：修正周期分界。
- `POST /api/runs/{id}/exclusions`：排除一段传感器故障数据。
- `POST /api/runs/{id}/recompute`：基于原始测点和指定规则版本生成新派生版本。

`src/test/java/com/example/batterylab/BatteryLabApplicationTests.java` 使用随机端口和独立 SQLite 文件，端到端覆盖：

- 上报成功后、确认前掉线，再重连确认，测点不重复也不丢失；
- 同一设备序号携带不同载荷进入 `CONFLICT`，旧值不覆盖且终态不可重启；
- 迟到样本被标记为 `LATE`，已发布步骤不倒退，同时生成需复核派生版本；
- 13 个确定性测点跨过周期端点，周期号、边界、容量和效率正确；
- 用 `rules/v2` 对 `rules/v1` 运行重算，旧版本保留，新版本使用指定规则；
- 周期分界修正和传感器故障排除均生成新的不可变派生版本。
